## 2. What Went Well

- **Review discipline scaled with risk.** The 3-layer adversarial review (Blind Hunter / Edge Case Hunter / Acceptance Auditor) ran on every story except 3.2 (which needed nothing); patch counts tracked pipeline centrality (3.2: 0 → 3.4/3.5/3.7: 12–16). Later stories cite earlier patch numbers — the review culture became self-referential.
- **Deterministic-in-C# discipline (FR-011).** `ComplexityRater` (3.5) became the explicit template for `PrefixAnalyzer` (3.6): anything deterministic stays out of Claude's hands. This directly de-risks Epic 4's `DeterministicAnalyser` (ADR-005).
- **Pattern reuse:** static-helper-for-testability (3.0 → 3.1), per-row sub-query isolation with sentinel (3.4 → 3.7), `required` init slots (3.6 → 3.7), null-filter pattern with story-precedent citations (3.5 → 3.6 → 3.7).
- **NFR-007 credential-leak hygiene** held under pressure: sanitized failure messages (3.1), transport-fault catch broadening that never echoes fault text (3.4), log-expansion suppression (3.5 P10), fixed-string per-user error logging (3.7).
- **Debt repayment happened inside the epic.** Story 3.8 paid down Epic 2 retro debt (T3 factory duplication, PREP-4 cancellation) and was deliberately sequenced before 3.4 as a gate so new tools couldn't inherit the old interface.
- **Forensic instrumentation paid off.** R-HF-4/R-HF-9 logging additions are why the R-HF-10 failure diagnosis took one log read instead of another paid run.
- **The correct-course machinery worked.** R-HF-10 exercised the full `bmad-correct-course` → retroactive mini-story → `bmad-code-review` flow — a worked example for future out-of-band changes.

## 3. What Didn't Go Well

- **"Validated by design is not validated" — repeated.** This was Epic 2 retro Lesson 1 and Action P1. The gate text was added to Story 3.4 (`epics.md:581–591`) but not enforced in practice: Stories 3.4–3.7 closed against mocked-only suites, and 6+ runtime defects (the R-HF cascade) only surfaced in later paid E2E runs. Story 3.4's own Debug Log records only `dotnet test`, no live run. The process improvement existed on paper and failed in execution.
- **PREP-3 (integration harness) never materialized** — the systemic root cause of the point above. Without a cheap live-validation loop, E2E deferrals accumulated until they detonated at epic close, at ~$0.40 per detonation.
- **The epic-level architectural miss:** Mode 1 context-window scaling. Story 3.5 raised the iteration cap to 200 assuming that sufficed. Reality: iter=2 fans out 14 parallel tool_use results; context accumulates toward the 200k window (~1.5M-token trajectory by iter≈30); iter=3 Claude call exceeds the 600s HttpClient timeout. R-HF-10's payload slim changed the wall-clock by +3.8s (627.7s → 631.5s) — payload *shape* was never the driver; accumulated tool-result *volume* is.
- **R-HF-10 procedural drift:** executed as a size-crept hotfix outside the `bmad-agent-dev` persona (self-flagged in the mini-story). The retroactive-story pattern recovered the audit trail, but the drift is worth naming.
- **Spec baselines drift silently.** Story 3.8 discovered the spec's "68 tests" baseline was stale (real: 86). Small, but a symptom of docs not updated in the same commit as reality (Epic 2 Action P4, still only partial).

## 6. 🚨 Significant Discoveries — Epic 4 Update Required: YES

1. **Large-tier structural bottleneck confirmed (R-HF-10 E2E).** The Epic 3 single-pass `AgentOrchestrator` cannot complete Mode 1 on ~200-table environments. Fix = ADR-004 batching (Story 4.3) + ADR-008 bounded two-pass contexts (Story 4.9/4.10 territory). Epic 4 planning must treat 4.3 + the two-pass refactor as early, not late.
2. **Gap G3 — ADR-008 two-pass orchestrator refactor is under-owned.** `architecture.md:886–888,922` mandates a structural `BuildPass1`/`BuildPass2` orchestrator refactor as "Phase 3 first implementation story," but no Epic 4 story carries it in its ACs: Story 4.9's ACs describe a *single* Claude invocation (ADR-006 enforcement), and 4.10 owns document layering, not orchestrator passes. This mirrors exactly the Epic 3 failure pattern ("owned by no story").
3. **AgentOrchestrator scaling gap (streaming, per-iter budget, tool_result fan-in payload budgeting)** remains owned by no story — must be absorbed into the Epic 4 plan or a dedicated story during sprint planning.
4. **Exit-gate reality:** Story 3.5's "first customer receives + validates a generated document" gate can only close against a Typical-tier environment until Epic 4 ships. Without a Typical-tier sandbox, it cannot close at all.
5. **Measurement caveat:** the "context size" diagnosis rests on wall-clock invariance (+3.8s), not a direct token count — post-slim iter=3 input size was never measured. Cheap instrumentation owed before the next paid run (Action A6).

**Wrong assumptions in current Epic 4 plan:** that Story 4.9 as-written covers the two-pass refactor; that story order 4.1→4.11 can be executed serially without pulling 4.3/two-pass forward.

## 11. Key Takeaways

1. **Process gates that live only in prose don't hold.** Epic 2's P1 gate existed in text and failed in behavior. Epic 4 gets per-story live-probe ACs (A2) — enforcement at the point of story creation, not epic-level intention.
2. **"Owned by no story" is the recurring failure signature.** Epic 3's context-scaling gap and Epic 4's G3 two-pass refactor gap are the same shape. Sprint planning must run an ADR→story-AC traceability check (A3).
3. **Forensic spend discipline worked.** Six failed E2E runs cost ~$1.60 total because each run was instrumented before it was paid for. Keep that order (A6 before any next run).
4. **The review pattern is a genuine asset.** 68→294 tests with escalating adversarial patch discipline is why R-HF-10 shipped clean in hours and why Epic 4 can move fast on top of it.
